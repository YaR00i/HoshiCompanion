# Hoshi 0.5 — вручную выбранное внешнее окно

## Использование
Обычный запуск по-прежнему не следит за другими приложениями.
В примерочной или ПКМ: «Выбрать окно под курсором · 4 с».
Наведи мышь ВНУТРЬ нужного окна и дождись конца отсчёта; кликать не надо.
Горизонтальное положение курсора выбирает место посадки на верхнем краю.
Над окном нужно место для головы/тела, а снизу — для ног.
Развёрнутые и полноэкранные окна намеренно не поддерживаются.
Для отмены: ПКМ → «Вернуться на пол» (также работает кнопка «Стоп»).
После сворачивания/закрытия/потери опоры возвращается на пол.
Повторно подключается только по явному выбору, не после каждого восстановления.
Перетаскивание Хоши снимает удержание; отпускание у той же опоры прикрепляет снова.
Просьба пройтись сначала возвращает на пол и ставит на ноги.
Прежняя собственная полочка остаётся доступна отдельно.

## Приватность и время жизни
window_geometry.py получает только выбранный HWND, его геометрию и состояние.
WindowFromPhysicalPoint вызывается один раз после отсчёта; EnumWindows не используется.
Не читаются заголовки/тексты/вкладки; нет снимков экрана, hooks и сетевых портов.
Класс окна и PID/TID используются внутри помощника для фильтра/проверки идентичности.
Процесс отвечает на JSON-запросы по stdio; нет фоновой службы или автозапуска.
Помощник завершается при отсоединении, EOF или 5 секундах без запросов.
Поле HWND и координаты не сохраняются в пользовательские настройки/историю.
Чужие окна не перемещаются, не активируются и не закрываются приложением.
Python берётся из локального python_path.txt; PATH/реестр не меняются.

## Координаты и ограничения
Границы берутся через DWM и приводятся к тому же DPI-контексту, что и окно Godot.
Малые невидимые рамки пересчитываются через physical/logical GetWindowRect.
Помощник использует GetWindowDpiAwarenessContext собственного окна Хоши.
Начало координат калибруется по ClientToScreen в этом же DPI-контексте.
Это важно при нескольких мониторах и разных настройках масштабирования.
GetSystemMetrics(SM_XVIRTUALSCREEN) не используется как надёжная замена калибровке.
Возврат на пол происходит при ошибке помощника или нехватке места для аватара.
Проверка PID/TID/класса снижает риск привязки к повторно использованному HWND.
Перекрытие опоры другим окном пока не учитывается: Хоши остаётся поверх окон.
Смена виртуального рабочего стола/скрытие может снять привязку.
Нет самостоятельных перескоков, поддержки полноэкранных игр и системных диалогов.
Ручной выбор конкретного браузера — отдельная пользовательская приёмка.

## Проверка и источники API
python tools\dev.py check — прежние проверки, без просмотра чужих окон.
python tools\dev.py shelf_windows — проверка собственной полочки.
python tools\dev.py external_windows — отдельный Tk-процесс с пустым тестовым окном.
