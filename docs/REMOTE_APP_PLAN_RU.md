# План: пульт → приложение и управление браузером

Записано 27.09.2026 для следующего чата. Сейчас пульт — веб-страница
(`remote/remote.html`), связь переживает блокировку телефона (см.
`docs/REMOTE_RU.md`, «Блокировка телефона»), YouTube управляется через
расширение Chrome `browser_extension/hoshi_apps`.

## Чего хочу

1. Связь, которая не рвётся, пока телефон заблокирован.
2. Управлять не только YouTube, а браузером вообще: видеть вкладки на телефоне.
3. Для знакомых сайтов (YouTube и тех, что добавим) — свои кнопки управления.
4. Идея: у многих сайтов есть мобильная версия — можно ли показывать её на
   телефоне и синхронизировать с компьютером.
5. Переключать, куда идёт звук ПК (наушники / телевизор / колонки).
6. Управлять плеером MPC-BE с пульта.
7. ИИ-помощники на ПК (Claude Code, ChatGPT Codex): видеть на телефоне их
   ответы и писать им обратно — официальные приложения долго подключаются.

## Шаги (по очереди, маленькими кусками)

### 1. Кнопки на экране блокировки (без приложения)
- Media Session API в странице пульта: пауза/дальше/назад YouTube прямо с
  экрана блокировки, как у музыкального плеера.
- Ограничение: браузер показывает такие кнопки только пока страница «играет»
  звук — нужна проверка на реальном Android/iPhone (тихий звук, батарея).
- Если не взлетает — сразу к шагу 3.

### 2. Вкладки браузера на пульте
- Расширение `hoshi_apps`: список вкладок (заголовок, сайт, иконка, какая
  активна), переключить/закрыть вкладку, открыть ссылку из «Моих действий».
- **Нужно моё решение по приватности**: сейчас расширение читает только
  youtube.com. Заголовки всех вкладок — это новое разрешение (записать в
  AGENTS.md и CLAUDE.md, как с YouTube).
- Вариант поскромнее: только сайты из белого списка, остальные — «вкладка».

### 3. Отдельное приложение на телефоне
- Кандидаты: PWA («Добавить на главный экран» — уже почти есть; фоновой связи
  не даёт), либо маленькое Android-приложение (фоновый сервис держит связь,
  уведомление с кнопками, работает на экране блокировки). Godot тоже может
  собрать Android-приложение — но для такого клиента проще нативный/Flutter.
- Протокол менять не нужно: приложение говорит с тем же `remote_bus.gd`
  (WebSocket 18771, привязка по коду/QR, `ping`/`pong`).
- iPhone: фоновая связь ограничена системой — только уведомления/виджеты.

### 4. Кнопки для знакомых сайтов
- Адаптер на сайт в расширении (как `youtube.js`): свой набор команд и
  состояния. Кандидаты: Twitch, Яндекс Музыка, Spotify web, Netflix/Кинопоиск.
- Всё через уже существующий протокол аддонов (`app_adapters.gd`).

### 5. Про «мобильную версию сайта на телефоне»
- Показать на телефоне ту же страницу и синхронизировать клики с ПК напрямую
  нельзя: это разные сессии браузера, сайты это не поддерживают.
- Реально: а) адаптер сайта (шаг 4) — кнопки делают то же, что на ПК;
  б) «Открыть на телефоне» — передать ссылку текущей вкладки, чтобы
  продолжить смотреть уже на телефоне.

## Обсуждение 27.09 (вечер): как делать

Похожие программы для вдохновения: KDE Connect (ближе всего по духу: медиа с
экрана блокировки, пересылка ссылок), Unified Remote (готовые «пульты» под
программы — как наши адаптеры), Chrome Remote Desktop / AnyDesk (весь экран —
слишком много), «Вкладки с других устройств» в Chrome. **В новом чате сначала
поискать в интернете готовые способы и библиотеки** (трансляция вкладки,
MediaStyle-уведомления, WebView-обёртки), чтобы не изобретать заново.

Три уровня управления браузером (делать по порядку 1 → 3 → 2):
1. **Пульт с кнопками**: список вкладок, переключить/закрыть, кнопки знакомых
   сайтов. Всё делает расширение Chrome. Дёшево и быстро.
2. **Посмотреть страницу**: расширение снимает видео ОДНОЙ вкладки
   (`chrome.tabCapture`) и передаёт на телефон по WebRTC; тап/прокрутка на
   телефоне → клик/прокрутка на ПК. Сложнее, тратит батарею.
3. **Открыть на телефоне**: передать ссылку текущей вкладки, открыть в браузере
   телефона (мобильная версия, свой вход). Замена идеи «синхронизировать
   мобильную версию» — две сессии браузера напрямую не синхронизируются.

Приложение — **только Android** (iPhone пока негде тестировать):
- Маленькое нативное приложение на Kotlin, внутри — наша же `remote.html` в
  WebView (кнопки и оформление переиспользуются).
- Нативная часть: фоновая служба держит связь (постоянное уведомление «Хоши на
  связи»), кнопки в уведомлении и на экране блокировки (MediaStyle), сканер QR,
  быстрые плитки в шторке.
- Протокол тот же (`remote_bus.gd`). Установка APK по кабелю/Wi-Fi через
  Android Studio, без магазина.
- Почему не PWA (нет фона и экрана блокировки), не Flutter (переписывать пульт),
  не Godot (тяжело, фон всё равно отдельно).

Решения за мной перед началом: приватность вкладок (все заголовки или белый
список); делать ли трансляцию вкладки и только ли по нажатию с заметным значком
на ПК; согласен ли на постоянное уведомление на телефоне.

## Программы на ПК: добавлять постепенно, по одной

Кроме сайтов в браузере — адаптеры для программ Windows (тот же протокол
аддонов `app_adapters.gd`, карточка на пульте как у YouTube).

**Первая — MPC-BE (Media Player Classic — Black Edition).** Хочу управлять им
с пульта.
- У MPC-BE есть встроенный веб-интерфейс: Настройки → «Веб-интерфейс»
  (Web Interface), порт по умолчанию 13579. Включать **только для этого ПК**
  (localhost), без доступа из сети.
- Команды: `http://127.0.0.1:13579/command.html` с номером команды
  (`wm_command`: пауза/играть, стоп, перемотка, громкость, следующий/предыдущий
  файл, полный экран). Состояние: `variables.html` (файл, позиция,
  длительность, играет ли, громкость).
- Адаптер можно сделать внутри Хоши (опрос раз в секунду, только пока MPC-BE
  запущен и пульт включён) — расширение не нужно. Номера команд и страницы
  проверить по документации MPC-BE в новом чате.
- Карточка на пульте: название файла, полоса времени, ⏪ ⏯ ⏩ ⏭, громкость,
  полный экран. Команды — только по нажатию человека, как у YouTube.
- Приватность: читаем только то, что MPC-BE сам отдаёт о текущем файле
  (имя файла, время). Решение записать в AGENTS.md/CLAUDE.md, как с YouTube.
  Внимание: `variables.html` отдаёт и **полный путь** к файлу (`filepath`,
  `filedir`) — его не берём и на телефон не передаём, только `file`.
- Громкость MPC-BE (`volumelevel`, `muted`): кнопки 🔉 🔊 🔈 на карточке
  (907/908/909) — добавлены 27.09 по моей просьбе.

Дальше по желанию — другие программы по тому же образцу.

## ИИ-помощники на телефоне: Claude Code и ChatGPT Codex (записано 27.09)

Хочу: на пульте вкладка «Помощники» — видно, чем закончил Claude Code / Codex на
ПК (текст ответа), и можно написать ответ с телефона. Официальные приложения
(Claude, ChatGPT) долго подключаются; наш пульт уже на связи в домашней сети.

Возможные способы (проверить в новом чате — **сначала поиск готовых решений**,
документация Claude Code и Codex меняется):
- **Узнать, что помощник закончил и что ответил.**
  Claude Code: «хуки» (hooks) — программа, которую Claude Code сам вызывает на
  событиях: закончил ответ (`Stop`), ждёт разрешения (`Notification`). Хук
  может передать Хоши событие и последний ответ по 127.0.0.1.
  Codex: настройка `notify` — тоже вызывает программу, когда ход закончен.
- **Написать обратно.** Разные пути, у каждого минусы:
  а) запуск в «безголовом» режиме с продолжением той же сессии (у Claude Code
     `claude -p --resume <сессия>`, у Codex `codex exec resume`) — ответ уйдёт
     в ту же беседу, но открытое окно на ПК может не показать его сразу;
  б) сессии, которые Хоши сама запускает через SDK (Claude Agent SDK / Codex
     app-server) — полный контроль, но это «свои» сессии, не окно приложения;
  в) вставить текст в окно приложения (эмуляция клавиатуры) — хрупко, не хочу.
- Вероятно, первым делом: а) только уведомление «Claude закончил / ждёт
  разрешения» на пульте; б) текст последнего ответа; в) ответ с телефона.

**Решения за мной до начала (это больше, чем всё, что было раньше):**
- Приватность: пульт впервые показывает **содержимое** — тексты бесед с ИИ
  (код, пути, всё, что там есть). Связь пульта — обычный WebSocket в домашней
  сети без шифрования; для текстов бесед, возможно, нужно шифрование.
- Безопасность: сейчас правило «телефон нажимает только готовые кнопки».
  Текст, отправленный ИИ-помощнику с доступом к компьютеру, — это по сути
  команда «сделай что угодно». Нужно явное исключение из правила и границы:
  только привязанный телефон; только сессии, которые я отметил на ПК; режим
  разрешений помощника не меняется с телефона; разрешать/запрещать его
  действия с телефона — отдельное решение.
- Какие сессии видны на пульте: все или только отмеченные на ПК.

## Адреса пульта (сделать до приложения, маленькая задача)
- На ПК несколько сетей: `Ethernet` 192.168.0.94 (домашняя), `AmneziaVPN`
  10.8.1.2, `Radmin VPN` 26.x. Работает только 10.8.1.2 — вероятно, на
  телефоне включён тот же AmneziaVPN, и связь идёт через VPN-сервер (медленнее;
  порт виден другим клиентам этого сервера, хоть и с кодом привязки).
  Проверить: выключить VPN на телефоне и открыть `http://192.168.0.94:18770/`.
- В окне «Пульт с телефона» подписывать адреса названием сети
  (`IP.get_local_interfaces()` → `friendly`), дать выбрать адрес для QR и
  запомнить выбор. Виртуальные/VPN-адаптеры помечать, а не прятать молча.

## Звук: переключение устройств (первым в порядке внедрения)

Решено 27.09: кнопки на пульте «Наушники · Телевизор · Колонки» — куда идёт
звук ПК, как выбор устройства в трее Windows. **Громкость не нужна** — регулирую
сам. Работает уже в нынешнем веб-пульте, приложение не требуется.

- **Без чужих программ.** Свой маленький помощник `tools/audio_devices.py`
  (Python + ctypes, как остальные помощники окон; ничего не скачиваем и не
  собираем): `list` — устройства вывода и какое главное, `set <id>` — сделать
  главным (только активное устройство из списка).
- Решено 27.09 (вариант «б»): переключаем только **обычное** главное
  (роли «Консоль» + «Мультимедиа»); главное **«для связи»** (Discord, звонки)
  не трогаем — оно остаётся на HyperX.
- Как устроено: список устройств — Core Audio (`IMMDeviceEnumerator`); смена
  устройства по умолчанию — недокументированный `IPolicyConfig` (так делают
  SoundSwitch/EarTrumpet; стабилен на Win10/11, но официальной кнопки у Windows
  нет).
- Windows помнит ~30 старых записей (мониторы, геймпад, Pico, LG TV по разу на
  каждое подключение) — в окне настройки показывать только активные.
- Устройства на моём ПК (27.09): «Наушники (HyperX Cloud III)», «LG TV (NVIDIA
  High Definition Audio)» — HDMI, есть только пока ТВ включён, «Динамики
  (Realtek(R) Audio)»; отключённые сейчас: Wireless Controller, USB Audio
  Device, Pico — на пульте не показывать.
- Нет устройства (ТВ выключен) → кнопка серая «нет на связи», не ошибка.
  **Проверено 27.09:** LG, выключенный пультом (режим ожидания), по HDMI
  остаётся для Windows активным — плитка не сереет. Windows тут не отличает
  «включён» от «спит». Решено оставить так; честно узнать, включён ли ТВ, можно
  будет через сетевой интерфейс LG (пункт 4 ниже).
- Некоторые старые программы продолжают играть в старое устройство до
  перезапуска; Chrome и большинство плееров переходят сами.
- Правила: какие устройства показывать и как их назвать — выбираю **на ПК**
  (окно рядом с «Моими действиями»); телефон видит только эти кнопки и
  передаёт id из этого списка, ничего своего.
- Приватность (решено): Хоши знает только **названия звуковых устройств** и
  какое сейчас главное. Какие программы играют и что — не читаем. Записано в
  AGENTS.md и CLAUDE.md.

Шаги:
1. ✅ Помощник **читает**: список устройств и какое главное (27.09).
2. ✅ Переключение: колонки → ТВ → наушники → обратно, связь осталась на
   HyperX; отключённое устройство помощник отказывается включать (27.09).
3. ✅ Окно на ПК «Звук на пульте» (какие показывать, имена) + карточка «Звук»
   на вкладке «Главное» (27.09; `scripts/sound_outputs.gd`, см. REMOTE_RU.md).
   Осталось: живая проверка с телефона.
4. Потом, по желанию: LG по сети (у webOS есть сетевой интерфейс) —
   узнать, включён ли ТВ (тогда плитка честно сереет), включить/выключить его,
   громкость самого ТВ. Нужна одноразовая привязка (подтвердить на экране ТВ)
   и моё решение по приватности. Отдельная задача.

## Правила, которые не меняются
- Только домашняя сеть, привязка по коду/QR.
- Телефон нажимает только готовые команды и «Мои действия», сам не задаёт,
  что запускать. Команды приложениям — только по нажатию человека.
- Каждое новое чтение данных (вкладки, другие сайты) — только после моего
  явного решения.
