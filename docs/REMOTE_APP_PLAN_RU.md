# План: пульт → приложение и управление браузером

Записано 27.09.2026 для следующего чата. Сейчас пульт — веб-страница
(`remote/remote.html`), связь переживает блокировку телефона (см.
`docs/REMOTE_RU.md`, «Блокировка телефона»), YouTube управляется через
расширение Chrome `browser_extension/hoshi_apps`.

## Чего хочу

1. Связь, которая не рвётся, пока телефон заблокирован.
2. Управлять не только YouTube, а браузером вообще: видеть вкладки на телефоне.
3. Для знакомых сайтов (YouTube и тех, что добавим) — свои кнопки управления.
4. Идея: у многих сайтов есть мобильная версия — можно ли показывать её на
   телефоне и синхронизировать с компьютером.

## Шаги (по очереди, маленькими кусками)

### 1. Кнопки на экране блокировки (без приложения)
- Media Session API в странице пульта: пауза/дальше/назад YouTube прямо с
  экрана блокировки, как у музыкального плеера.
- Ограничение: браузер показывает такие кнопки только пока страница «играет»
  звук — нужна проверка на реальном Android/iPhone (тихий звук, батарея).
- Если не взлетает — сразу к шагу 3.

### 2. Вкладки браузера на пульте
- Расширение `hoshi_apps`: список вкладок (заголовок, сайт, иконка, какая
  активна), переключить/закрыть вкладку, открыть ссылку из «Моих действий».
- **Нужно моё решение по приватности**: сейчас расширение читает только
  youtube.com. Заголовки всех вкладок — это новое разрешение (записать в
  AGENTS.md и CLAUDE.md, как с YouTube).
- Вариант поскромнее: только сайты из белого списка, остальные — «вкладка».

### 3. Отдельное приложение на телефоне
- Кандидаты: PWA («Добавить на главный экран» — уже почти есть; фоновой связи
  не даёт), либо маленькое Android-приложение (фоновый сервис держит связь,
  уведомление с кнопками, работает на экране блокировки). Godot тоже может
  собрать Android-приложение — но для такого клиента проще нативный/Flutter.
- Протокол менять не нужно: приложение говорит с тем же `remote_bus.gd`
  (WebSocket 18771, привязка по коду/QR, `ping`/`pong`).
- iPhone: фоновая связь ограничена системой — только уведомления/виджеты.

### 4. Кнопки для знакомых сайтов
- Адаптер на сайт в расширении (как `youtube.js`): свой набор команд и
  состояния. Кандидаты: Twitch, Яндекс Музыка, Spotify web, Netflix/Кинопоиск.
- Всё через уже существующий протокол аддонов (`app_adapters.gd`).

### 5. Про «мобильную версию сайта на телефоне»
- Показать на телефоне ту же страницу и синхронизировать клики с ПК напрямую
  нельзя: это разные сессии браузера, сайты это не поддерживают.
- Реально: а) адаптер сайта (шаг 4) — кнопки делают то же, что на ПК;
  б) «Открыть на телефоне» — передать ссылку текущей вкладки, чтобы
  продолжить смотреть уже на телефоне.

## Правила, которые не меняются
- Только домашняя сеть, привязка по коду/QR.
- Телефон нажимает только готовые команды и «Мои действия», сам не задаёт,
  что запускать. Команды приложениям — только по нажатию человека.
- Каждое новое чтение данных (вкладки, другие сайты) — только после моего
  явного решения.

## С чего начать новый чат
Прочитать `CLAUDE.md`, `AGENTS.md`, `docs/REMOTE_RU.md` и этот файл. Начать с
аудита шага 1 (Media Session) и вопроса про приватность вкладок (шаг 2).
