# Линии внутри окон — первый диагностический срез

В меню Хоши выбери «Видимые края окна · 1 кадр · 4 с», затем наведи курсор на
браузер, Steam или другое открытое окно. Через четыре секунды появится
схематичная карта найденных горизонтальных краёв. Нажатие на линию показывает
тип элемента и размер. В заголовке и сводке указано, каким способом получена
карта: «Кадр» или «Структура». Для нового выбора нужно ещё раз навести курсор
на окно после нажатия соответствующей кнопки.

Это пока **проверка распознавания**, а не новая прогулка: Хоши не прыгает на
линии, не нажимает кнопки и не перемещает окно. Внешний вид окна не копируется
в карту. Длинный прямоугольник элемента может быть перекрыт другим элементом;
поэтому найденная линия ещё не означает безопасную опору.

Поиск запускается только вручную, работает с одним выбранным окном и завершает
помощник после одного результата. Режим «Структура окна · без снимка» использует UI Automation:
получает типы и прямоугольники, но не запрашивает имена, текст, значения полей
или содержимое чатов. Если линий больше 24, карта показывает выборку от начала
до конца списка. Обход ограничен 240 элементами, глубиной 12 и шестью
секундами. Браузер может скрыть элементы страницы, пока его режим доступности
не активен; Discord и Steam тоже могут не раскрывать нужные части интерфейса.

В этом случае в меню или в окне карты нажми **«Найти видимые края»**. Это
отдельный ручной режим: он снимает один кадр только выбранного окна средствами
Windows Graphics Capture, ищет горизонтальные края и повторяющиеся строки
элементов, затем возвращает Хоши только координаты. Фиолетовые линии на карте —
края, бирюзовые — строки интерфейса. Строка помогает понять устройство окна,
но сама по себе не является опорой. Результаты распределены по высоте окна,
чтобы верхняя панель не вытесняла нижние кнопки. Текст не распознаётся, изображение не сохраняется
и не отправляется по сети. Этот режим видит содержимое выбранного окна во время
анализа, поэтому не запускается автоматически. Привычный поиск по структуре
остаётся без захвата изображения.

Для визуального режима требуется `windows-capture==2.0.1` (устанавливает также
NumPy и OpenCV). На этой машине зависимость уже установлена локально в
`.workspace/surface-deps`; для другой установки:
`python -m pip install --target .workspace/surface-deps --only-binary=:all: windows-capture==2.0.1`.
Папка игнорируется Git и не входит в исходники проекта. Если модуль отсутствует,
обычный поиск продолжит работать, а визуальный режим сообщит о зависимости.
Визуальные края не гарантируют пригодность для ходьбы: линия может принадлежать
тексту, тени или перекрытому элементу.

Чтобы перейти к прыжку/ходьбе, нужно проверить достаточную ширину, видимость,
изменения при прокрутке, координаты DPI и место для всего окна Хоши. Движение
самого чужого окна при приземлении остаётся отдельной будущей анимацией.

Локальные проверки используют только свои тестовые окна:
`python tests/test_window_surfaces.py` и `python tests/test_window_surfaces_browser.py`.
