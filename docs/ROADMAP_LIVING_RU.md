# Hoshi Companion — roadmap после 0.7

Этот план развивает Hoshi от набора отдельных анимаций к маленькому живому desktop-персонажу.
Главный принцип: сначала осмысленный выбор поведения, затем выразительность, и только потом
долгая память/характер. Не строить большой универсальный Behavior Tree или GOAP без реальной
необходимости.

Карта конкретных занятий по местам и порядок проверки первого запуска:
`BEHAVIOR_PLACES_RU.md`.

## Нулевая граница — закрыть 0.7

0.7 остаётся release candidate до ручной приёмки.

Перед merge в main:
- дверь не пересекает Hoshi при входе/выходе;
- прозрачная область окна пропускает мышь, сама Hoshi остаётся интерактивной;
- surface walk / side support / moving window выглядят естественно;
- carry / jump / fall / landing не имеют явных визуальных поломок;
- автономия не делает бессмысленных stand -> sit и walk -> sit петель;
- приватный VRM не попадает в Git.

Новые крупные подсистемы не смешивать с исправлениями 0.7.

## 0.8 — Living Intentions

Цель: Hoshi не просто запускает случайное действие, а выбирает короткое намерение,
помнит, что только что делала, и естественно продолжает начатое.

### 0.8.0 — каркас Intent Planner

Добавить небольшой локальный слой планирования:
- BehaviorContext: где Hoshi находится, чем занята, можно ли идти/сидеть/прыгать;
- Intent: короткая цель — observe, explore_floor, explore_surface, rest, visit_side, leave_support, social_react;
- ActionStep: конкретный существующий механизм — walk, sit, look, side, jump, return;
- preconditions до начала анимации;
- interruption rules: пользователь всегда имеет приоритет;
- cooldown + novelty memory последних 4–6 действий;
- один активный intent, максимум 2–4 шага.

Сначала planner только выбирает и логирует решение. Существующие controllers остаются
владельцами движения и поз.

Definition of done:
- одинаковый seed + context даёт воспроизводимое решение;
- невозможное действие отбрасывается до изменения позы;
- нет повторения одного типа действия три раза подряд;
- manual input мгновенно отменяет intent;
- старые ручные команды продолжают работать.

## 0.8.1 — жизнь на полу

Разнообразить обычное пребывание внизу экрана:
- прогулка без обязательной посадки после неё;
- остановиться и осмотреться;
- отдельный curious peek с наклоном вперёд;
- отдельный едва заметный перенос веса, не смешанный с peek;
- кисти / плечи как самостоятельные спокойные микрожесты;
- редкий самостоятельный wave только в playful;
- сесть отдохнуть как отдельное решение;
- после отдыха: встать, осмотреться, пройтись или остаться спокойно стоять;
- длина маршрута и частота решений зависят от activity.

Activity должен менять именно выбор:
- Quiet: стоять, наблюдать, редко отдыхать/двигаться;
- Normal: смешанный режим;
- Playful: больше перемещения, коротких жестов и смен состояния, меньше долгого отдыха.

Definition of done:
за 3–5 минут наблюдения нет очевидного короткого цикла из двух-трёх действий.

## 0.8.2 — жизнь на окнах и полочках

Поверхность становится отдельным местом, а не только позой сидения:
- сначала проверка маршрута, потом вставание;
- пройтись по краю и выбрать новую точку посадки;
- просто пересесть в другую часть края;
- посмотреть вниз;
- поболтать ногами;
- откинуться;
- слегка балансировать;
- на подходящем внешнем окне посетить левую/правую боковую рамку;
- самостоятельно вернуться с боковой рамки наверх;
- иногда решить покинуть окно и вернуться на пол.

Учитывать историю:
- не выбирать ту же точку сразу;
- не делать side -> side на одной стороне подряд;
- после активной прогулки чаще выбирать спокойное действие.

Definition of done:
Hoshi может прожить короткую последовательность вроде
сидит -> смотрит вниз -> проходит по краю -> садится в другом месте
без телепорта и бессмысленных переходов.

## 0.8.3 — выразительные переходы

Отдельный visual polish существующих движений:
- carry: настоящая инерция тела, рук и ног, мягкое успокоение после остановки;
- jump: anticipation -> takeoff -> flight -> landing;
- fall: небольшая реакция/группировка, зависящая от высоты;
- landing: пружинящая посадка + восстановление равновесия;
- переход sit <-> stand на краю;
- side support entry/exit;
- дверь остаётся отдельным cinematic context.

Не менять владельцев:
AirMotion — траектория;
ContextPose — временная поза;
Locomotion/Gait — шаги;
Posture/EdgePose — опора.

Definition of done:
по одному стоп-кадру можно понять, находится Hoshi в carry, jump, fall или landing.

## 0.9 — Personality State

Только после того, как сами действия уже разнообразны.

Добавить медленные внутренние параметры:
- energy;
- curiosity;
- comfort/rest desire;
- social attention.

Это не симулятор потребностей и не Tamagotchi: значения только мягко смещают веса intent'ов.
Не должно быть наказаний пользователю, обязательного ухода или навязчивых уведомлений.

Activity остаётся явным пользовательским профилем, personality state — кратковременным
контекстом поверх него.

Примеры:
- долго стояла -> немного растёт желание сменить место;
- недавно много ходила -> спокойные действия получают больший вес;
- пользователь погладил -> короткое повышение social attention;
- долго сидит на окне -> может заинтересоваться другой точкой или полом.

## 0.9.1 — короткая память поведения

Небольшая session-memory:
- последние intents/actions;
- последние позиции на поверхности;
- недавно использованные жесты;
- время последнего взаимодействия пользователя;
- текущая маленькая цель.

По умолчанию это память текущего запуска. Сохранение между запусками вводить только
для действительно полезных предпочтений, а не для полной истории поведения.

## 0.9.2 — характер Hoshi

Добавлять характер через веса и выбор действий, а не через сотни специальных условий:
- любопытная, но не гиперактивная;
- тёпло реагирует на внимание;
- иногда действует сама;
- playful ощущается игривой, а не просто ускоренной;
- quiet ощущается спокойной, а не выключенной.

Текстовые реплики должны соответствовать действию и быть редкими.

## 0.10 — Desktop World

Расширять только geometry/state-based взаимодействие:
- лучше понимать углы окна;
- аккуратные переходы top edge <-> side;
- несколько безопасных точек интереса на большой поверхности;
- multi-monitor transitions только после отдельной безопасной архитектуры;
- app-owned предметы/места можно добавлять без чтения чужого содержимого.

Не читать заголовки, текст или пиксели чужих окон ради понимания контекста.

## Порядок реализации

1. Закончить ручную приёмку 0.7 и исправить остаточные визуальные дефекты.
2. Intent Planner skeleton без изменения визуального поведения.
3. Novelty/cooldown/history и deterministic tests — реализовано в shadow planner; candidate report хранит причины отказа.
4. Перевести floor autonomy на intents — первая миграция: observe / explore_floor / rest / social_react исполняются planner-цепочками.
5. Перевести surface autonomy на intents — explore_surface / visit_side / leave_support / observe используют существующий SurfaceController.
6. Добавить короткие 2–4 step chains — реализованы вариантные mini-scenes для floor/surface с отдельной памятью вариантов и явными micro-gestures.
7. Visual polish carry/jump/fall/landing — AirMotion отдаёт phase/velocity/impact, ContextPose использует их для inertia, anticipation, tuck/brace и landing recovery.
8. Personality State.
9. Session-memory и более узнаваемый характер.
10. Только после этого расширять desktop-world возможности.

## Правило для каждого этапа

Каждая новая возможность проходит одинаковый цикл:
1. маленький архитектурный контракт;
2. реализация без захвата чужих обязанностей;
3. deterministic/headless tests;
4. Windows fixture tests, если затронут native desktop;
5. только app-owned visual capture;
6. ручная приёмка;
7. отдельный checkpoint commit.

Автотесты подтверждают механику и регрессии, но никогда не заменяют ручную оценку
того, выглядит ли Hoshi живой и естественной.
